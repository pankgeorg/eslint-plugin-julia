# Default configuration: which rules are on, and why

`recommended` turns on rules that catch likely bugs with near-zero false positives (ESLint's own bar): **error** when a finding is almost always a bug (Julia rejects the code, or the check can never be right), **warn** when it is a probable bug with occasional deliberate uses. Everything else is opt-in; `strict` turns all of it on as warnings (`julia.configs.strict`). `strict` also gives `no-undef` the option `fragments: "report"`: unresolved reads in files whose includer isn't visible are reported too, with a lower-confidence message.

Evidence: findings with every rule on, over a 2,518-file sample of real Julia code (Julia base/stdlib/test and package sources; one in ten files of a 25,174-file corpus), and over Pluto.jl (138 files) and Malt.jl (13 files) with their environments instantiated. Per-rule classification of findings is in the pull requests.

77 rules: 12 recommended as error, 14 as warn, 51 opt-in.
